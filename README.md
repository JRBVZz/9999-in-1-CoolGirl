# 9999 in 1 To CoolGirl ROM Builder

9999 in 1 To CoolGirl ROM Builder сборщик мультиигровых ROM для флеш-картриджей **COOLGIRL** (Famicom / Денди). Из Пиратского ROM 9999 in 1 за основу был взят ROM [9999_in_1_rev_1_1_[p]_[!]_by_Guyver](http://chief-net.ru/index.php?option=com_content&task=view&id=234&Itemid=67)  CRC32: 92CE2490 и папки с играми собирает единый образ `.nes` / `.bin`, который можно запустить в эмуляторе или записать на картридж.

Написан на **Python**, вся настройка через один файл `settings.ini`.

## Возможности

- Автоматически объединяет до 9999 игр в один образ для картриджа COOLGIRL ограничение только в размере флеш, 64mb или 128mb вряд ли получится записать больше 3000 игр.
- Меню пиратского картриджа «9999 in 1» с **пляжем, закатом и летящими чайками
под музыку** **«Unchained Melody»** одно из самых узнаваемых воспоминаний эпохи Dendy
- **на выбор классическая длина имён игр ограничена 11 символами или Длинные названия** игр с бегущей строкой до 48 символов
- Автоопределение региона **NTSC / PAL / Денди** и подбор темпа музыки 60 50 герц авто
- Сохранения для игр с «батарейкой» прямо во флеш-памяти (до 255)
- Автоматические **CRC32-фиксы** проблемных игр (`nes-fixes.json`): размер PRG RAM, маппер, несовместимость с Денди
- Вывод в формате **NES 2.0** (`.nes`) или «сыром» бинарнике (`.bin`) для программатора
- **Доп. меню настроек прямо в картридже** (`START` + `A`): вкл./выкл. музыки и заставки + быстрый переход к началу списка; настройки сохраняются в памяти картриджа подробнее ниже

## Список игр (`list = txt` / `csv`)

По умолчанию (`list = none`) билдер просто сканирует папку `roms/` и берёт **все** `.nes`-файлы в алфавитном порядке, а имя в меню = имя файла без расширения. Список нужен, когда хочется **самому задать порядок игр в меню**, **переименовать** их или **включить в сборку только часть** ромов из папки.

Источник списка выбирается ключом `list` в секции `[roms]`:

- `list = none` - список не используется (порядок и имена из папки `roms/`).
- `list = txt` - читается файл **`games.list`** (простой текст).
- `list = csv` - читается файл **`games.csv`** (таблица, удобно править в Excel).

<aside>

**Шаблон создаётся автоматически.** Если включить `list = txt`/`csv`, а файла ещё нет, при первой сборке билдер создаст его сам по содержимому `roms/` (имена в меню = имя файла без `.nes`, ЗАГЛАВНЫМИ). В лог выводится `📝 Создан шаблон списка…`. После этого отредактируйте порядок/имена и запустите сборку снова.

</aside>

### Формат `txt` (`games.list`)

Добавлен для совместимости со старыми списками. По одной игре на строку. Имя в меню отделяется вертикальной чертой |

```
; Список игр — порядок строк = порядок в меню
Adventure Island.nes | ОСТРОВ ПРИКЛЮЧЕНИЙ
Battle City.nes | ТАНЧИКИ
Contra.nes                ; имя не указано → будет "Contra"
; Duck Tales.nes          ; строка закомментирована → игра не войдёт
- | СТРАТЕГИИ             ; разделитель/категория (пока игнорируется)
```

- `файл.nes | ИМЯ` задать своё имя в меню.
- `файл.nes` без черты: имя = имя файла без `.nes`.
- Строки, начинающиеся с `;` или `#` — комментарии (игнорируются).
- Строки, начинающиеся с `-`  разделитель/категория; в текущей сборке отдельной строки-разделителя в меню нет, поэтому они просто пропускаются, лучше не использовать.
- Пустые строки игнорируются.

### Формат `csv` (`games.csv`)

Две колонки `filename` и `menu_name`. Стандартный разделитель **точка с запятой `;`** (запятая может встречаться в названиях игр, поэтому как разделитель не используется; для старых файлов есть запасной разбор по `,` и табуляции). Кодировка UTF-8.

```
filename;menu_name
Adventure Island.nes;ОСТРОВ ПРИКЛЮЧЕНИЙ
Battle City.nes;ТАНЧИКИ
Contra.nes;
```

- Первая строка с заголовком (`filename`/`file`/`имя файла`/`файл`) распознаётся и пропускается.
- Пустое `menu_name` → имя = имя файла без `.nes`.
- Имена с разделителем внутри можно брать в кавычки `"…"`.

### Порядок и отбор игр

- **Порядок в меню** = порядок строк в списке.
- **Файлы сопоставляются по имени** (без учёта регистра, берётся только имя файла без пути).
- Файл указан в списке, но **отсутствует** в `roms/` → игра пропускается с предупреждением `⚠️ … не найден`.
- Файл **есть в `roms/`, но не указан** в списке → он **не войдёт** в сборку (выводится `ℹ️ … не из списка`). Это удобно: в `roms/` можно держать «запас», а собирать только нужное.
- Чтобы временно убрать игру закомментируйте её строку (`;`) или удалите из списка.

<aside>

Длина имени в меню всё равно ограничена настройками `[menu]`: при `name_mode = 2` — до `name_max` символов (макс. 48), на экране видно `name_visible` (длиннее прокручивается бегущей строкой); при `name_mode = 1`  11 символов.

</aside>

## Доп. меню (настройки) «PRESS A FOR OPTIONS»

В само меню встроено **дополнительное меню настроек**: его можно открыть прямо на картридже или в эмуляторе, не пересобирая ROM. Оттуда включается/выключается музыка и заставка, а также есть быстрый возврат к началу списка. Выбранные настройки запоминаются между включениями.

### Как открыть и закрыть

- На любом из 14 экранов меню **зажмите `START`** внизу появится подсказка **`PRESS A FOR OPTIONS`**.
- Не отпуская `START`, **нажмите `A`** откроется доп. меню (то есть комбинация **`START` + `A`**).
- Для выхода нажмите **`START`** (внизу меню есть подсказка **`PRESS START TO EXIT`**).

### Пункты меню

| Пункт | Что делает |
| --- | --- |
| `MUSIC ON` / `MUSIC OFF` | Включает/выключает музыку меню. Срабатывает сразу музыка стартует или глушится. |
| `INTRO ON` / `INTRO OFF` | Включает/выключает начальную заставку (падающие 9999) при старте картриджа. |
| `FIRST PAGE` | Быстрый прыжок к самому началу списка (первая игра / первая страница) |

### Управление

- **↑ / ↓** — переключение между `MUSIC` и `INTRO` (левая колонка).
- **← / →** — переход между левой колонкой (переключатели) и правой кнопкой `FIRST PAGE`.
- **`A`** — переключить выбранный пункт (или активировать `FIRST PAGE`).
- **`START`** — выйти из доп. меню.

### Сохранение настроек

<aside>

Настройки (музыка / заставка) сохраняются в **энергонезависимой памяти картриджа** (SRAM с сигнатурой, адреса `$7FF0–$7FF2`) и восстанавливаются при следующем включении. Если SRAM/батарейка недоступна, при каждом запуске берутся значения по умолчанию.

**По умолчанию:** музыка **вкл.**, заставка **вкл.**

</aside>

## Фиксы проблемных игр`nes-fixes.json`

Некоторые ромы не запускаются, виснут или не сохраняют прогресс на 9999 in 1, потому что в их iNES-заголовке указаны неверные данные (маппер, зеркалирование, батарейка) либо они несовместимы с конкретным регионом. `nes-fixes.json` база ручных правок: для каждой игры по её контрольной сумме задаются корректные параметры, которые билдер применяет **поверх** заголовка при сборке.

### Когда нужен фикс

- Игра не запускается / чёрный экран → чаще всего неверный **mapper**. или неправильная конфигурация плис.
- Рябь или неправильное зеркалирование картинки → **mirroring**.
- Не сохраняется прогресс (или зря занят слот сохранения) → **battery** / **prg_ram_size**.
- Виснет только на Денди (или только на NTSC/PAL) → **will_not_work_on_***.

### Шаг 1. Вычислить контрольную сумму

Ключ записи это **CRC32 от данных PRG + CHR** (без 16-байтного iNES-заголовка и трейнера), 8 hex-символов в нижнем регистре.

Самый простой способ **запустить сборку**: билдер печатает CRC каждой игры в лог (строка вида `✅ Game: mapper=4 … CRC=a1b2c3d4`). Оттуда сумму можно просто скопировать.

Либо посчитать вручную на Python:

```python
import zlib

with open("game.nes", "rb") as f:
    raw = f.read()

trainer = 512 if (raw[6] & 4) else 0
prg = raw[4] * 16384
chr = raw[5] * 8192
start = 16 + trainer
data = raw[start:start + prg + chr]

print(f"{zlib.crc32(data) & 0xFFFFFFFF:08x}")
```

**Battery-фиксы** (только параметры сохранений) ищутся не по CRC32, а по **SHA1-префиксу**.

<aside>

**Что такое SHA1-префикс?**

**SHA1** это ещё одна контрольная сумма (хеш), как CRC32, только длиннее и надёжнее: для любого набора данных она даёт строку из **40** hex-символов уникальный «отпечаток» файла.

**Префикс** это просто **первые 16 символов** из этих 40 (остальные отбрасываются: 16 знаков уже достаточно, чтобы игры не путались между собой, а ключ получается короче).

Считается он от **тех же байтов**, что и CRC32, данных PRG + CHR без 16-байтного заголовка.

</aside>

Например, если полный SHA1 данных = `1f3c9a02b7d45e6688a1c0d2…` (всего 40 знаков), то ключом в `nes-fixes.json` станут первые 16 `1f3c9a02b7d45e66`.

Получить такой префикс:

```python
import hashlib
print(hashlib.sha1(data).hexdigest()[:16])
```

<aside>

Ключ из `8` символов = CRC32 (mapper / mirroring / совместимость / prg_ram), ключ из `16` символов = SHA1-префикс (battery). Если для одной игры есть обе записи они объединяются, причём значения из **CRC32 имеют приоритет** (в поставляемой базе пересечений нет ключи разных типов не дублируют друг друга).

**Важно про сохранения:** *включение* батарейки (`battery: true`) задаётся через **SHA1**-ключ, а *размер* PRG-RAM и *отключение* сейва (`prg_ram_size: 0`) — через **CRC32**-ключ. То есть «параметры сохранений» завязаны не только на SHA1.

</aside>

### Шаг 2. Добавить запись

Откройте `nes-fixes.json` и добавьте объект, где ключ посчитанная сумма, а значение нужные параметры:

```json
{
  "78b657ac": {
    "description": "Armadillo (J)",
    "mapper": "118",
    "will_not_work_on_dendy": true
  },
  "af5d7aa2": {
    "description": "Clu Clu Land",
    "mirroring": "Horizontal"
  }
}
```

Поле `description` ни на что не влияет это подпись для лога и удобства.

Пример **battery-фикса** ключом служит 16-символьный SHA1-префикс (а не 8-символьный CRC32):

```json
{
  "1f3c9a02b7d45e66": {
    "description": "Some Game (J)",
    "battery": true,
    "prg_ram_size": 16
  }
}
```

### Доступные параметры

| Параметр | Значения | Что делает |
| --- | --- | --- |
| `description` | строка | подпись игры для лога (необязательна) |
| `mapper` | строка с номером: `"4"`, `"118"`, `"000"` | принудительно задаёт номер маппера |
| `mirroring` | `"Horizontal"` / `"Vertical"` / `"FourScreenVram"` | переопределяет зеркалирование |
| `battery` | `true` / `false` | включает / выключает сохранения |
| `prg_ram_size` | `0` / `8` / `16` / `32` | размер PRG-RAM в КБ (см. ниже) |
| `will_not_work_on_dendy` | `true` | несовместима с Денди |
| `will_not_work_on_ntsc` | `true` | несовместима с NTSC |
| `will_not_work_on_pal` | `true` | несовместима с PAL |
| `will_not_work_on_new_dendy` | `true` | несовместима с «новыми» Денди |

<aside>

**Про `prg_ram_size` (КБ):**

- `0` в заголовке «соврали» про батарейку: сохранения отключаются, слот не занимается.
- `8` стандарт для большинства battery-игр.
- `16` SUROM/SXROM и стратегии Koei (Romance of the 3 Kingdoms, Nobunaga's Ambition, Genghis Khan).
- `32` **не поддерживается** аппаратно (CoolGirl-Verilog): игра будет пропущена при сборке с предупреждением. Иные значения игнорируются.
</aside>

В одной записи можно комбинировать несколько параметров. После правки `nes-fixes.json` просто пересоберите ром в логе для каждой применённой записи появится отметка `[FIX …]`.

## Шрифт и кириллица

Патч шрифта настраивается в `font_patch.ini`:

- Секция `[atlas]` перерисовывает базовый ASCII из `font.png` (тайлы 8×8).
- Кириллица (А–Я) и спецсимволы распределяются автоматически по свободным слотам тайлов.

### Добавление новых тайлов (символов и иконок) Тестовая функция

Меню рисуется тайлами **8×8 пикселей**. Кроме базовой таблицы (33 буквы кириллицы, `&` и спецсимволы) можно добавить **свои** символы и иконки, например ★ или ♥. Всего в таблице кастомов помещается до 32 слотов. Добавление работает в тестовом режиме и до конца не доработана, возможны баги и ошибки!

#### Папка `tiles/`

Просто положите файл тайла в папку `tiles/` (путь задаётся ключом `tiles_dir` в секции `[font]`, по умолчанию `tiles`) при следующей сборке он автоматически станет кастомным тайлом. Править `.ini` при этом не нужно.

<img width="480" height="420" alt="3" src="https://github.com/user-attachments/assets/f96036b8-05a2-478b-9806-815b5d918a5b" />


Поддерживаемые форматы файла:

- **`.png`** берётся **верхний-левый тайл 8×8** (файл может быть больше, но используются только эти 8×8). Цвета читаются **в той же палитре, что и `font.png`** **3 цвета**, параметры берутся из секции `[colors]` файла `font_patch.ini`:
    - `white` (по умолчанию `#FFFFFF`) → «чернила» (индекс 3);
    - `black` (по умолчанию `#000000`) → второй цвет / «тень» (индекс 0);
    - `empty`-маркер (по умолчанию `#FF0000`) →  фон (индекс 2);
    - неизвестный цвет → при `unknown_as_empty = 1` уходит в фон, при `0` тайл пропускается с предупреждением (сборка не ломается);
    - допуски совпадения цвета (`tolerance` / `*_tolerance`) тоже берутся из `font_patch.ini`;
    - если `font_patch.ini` недоступен — работает упрощённый ч/б режим: `alpha < 128` → фон; `яркость < 128` и `alpha ≥ 128` → чернила; иначе фон.
    
    Таким образом кастомный тайл можно рисовать **в том же дизайне**, что и `font.png` (белый = видимый пиксель/«чернила», чёрный = второй цвет, красный = фон).
    

Имя файла задаёт, какой это символ и на каких экранах меню он появится:

| Имя файла | Что получится |
| --- | --- |
| `★.png` | символ ★ на всех экранах |
| `U+2665.png` | символ ♥ (по коду Unicode — для символов, недопустимых в имени файла) |
| `★@13.png` | только экран 13 |
| `★@5-10.png` | экраны 5–10 |
| `★@0,5,7.png` | экраны 0, 5 и 7 |
| `★@all.png` | все экраны (явная форма) |
| `T+{1}.png` | тайл-тэг `{1}` (см. ниже), все экраны |
| `T+{1}@13.png` | тэг `{1}`, только экран 13 |
- Всего в меню **14 экранов** (0–13); без `@`-суффикса символ добавляется на все.
- Файлы `readme`/`_readme` и всё, кроме `.png` / `.chr` / `.bin`, игнорируются.

<aside>

Если нужный символ нельзя записать в имя файла (или ОС его не разрешает) используйте форму `U+XXXX` с кодом Unicode, например `U+2665.png` для ♥.

</aside>

#### Тайлы-тэги `T+{…}` и символы в именах игр

Кроме одиночного символа и `U+XXXX`, тайл можно привязать к **тэгу** произвольному токену в фигурных скобках. Имя файла: `T+{тэг}.png` (можно с `@`-экранами: `T+{1}@13.png`).

- Тэг должен быть в фигурных скобках и непустым: `{1}`, `{flag}`, `{145}`.
- При сборке тэг маппится на свободный код-поинт из области Unicode PUA (`U+E000..U+F8FF`).
- В списке игр (`games.list` / `games.csv`) вы пишете тэг **как есть** — `{1}` — а при сборке `expand_tags()` подставляет вместо него ваш тайл.

Зачем это нужно: имя-тэг состоит только из ASCII-символов, поэтому не ломается, если CSV сохранён в ANSI/CP1251 (Excel), в отличие от «живых» значков ★/♥/■.

<aside>

**Два способа вставить кастомный значок в название игры:**

- **По коду Unicode:** в имени пишете `{U+XXXX}` перед кодированием это разворачивается в реальный символ (например `MARIO {U+2665}` → `MARIO ♥`). Подходит, если значок уже добавлен как `U+XXXX.png`.
- **По тэгу:** добавляете `T+{1}.png` и в названии пишете `{1}` `expand_tags()` подставит ваш тайл. Удобно для своих иконок без привязки к конкретному коду.
</aside>

#### Как символы попадают в меню

Размещением занимается `multi_alt`: он анализирует все 14 экранов, находит свободные тайлы и раскладывает кастомы по свободным слотам (`$DD..$FC` для кириллицы, `$AE..$D6` для спецсимволов), сам проверяя коллизии с фоном. Вручную назначать номера тайлов не нужно.

- Слотов конечное число: если свободных не осталось, лишние символы пропускаются (а при `strict = 1` в `[general]` сборка завершится ошибкой).
- Если символ из `tiles/` уже есть в базовой таблице, версия из `tiles/` его заменяет.
- Если папка `tiles/` есть, шаблон `multi_alt.ini` при сборке не создаётся drop-in достаточно.

## Подробно как это работает

Конвейер сборки (упрощённо):

1. Чтение `settings.ini` и пользовательской конфигурации.
2. Сбор списка игр из папки `roms/` или списка (txt/csv).
3. Применение CRC32-фиксов из `nes-fixes.json` (PRG RAM, маппер, несовместимость с Денди).
4. Извлечение PRG/CHR каждой игры, определение маппера и значений регистров.
5. Патч шрифта и формирование меню (имена, длинные названия с прокруткой).
6. Подбор темпа музыки под NTSC / PAL / Денди.
7. Размещение игр во флеше с выравниванием по 0x4000.
8. Сборка сервисного банка, банка данных и фиксированного банка.
9. Резервирование области сохранений (battery saves) вверху флеша.
10. Ассемблирование (`asm6502`).
11. Сборка итогового образа: заголовок NES 2.0 для `.nes` либо сырой флеш для `.bin`.

### Карта флеш-памяти

| Смещение | Область |
| --- | --- |
| `0x00000` | CHR меню (8 КБ) |
| `0x04000` | сервисный банк (16 КБ) |
| `0x08000` | банк данных (16 КБ) |
| `0x1C000` | фиксированный банк (FIXED_BANK) |
| `0x20000` | каталог уникальных игр (UNIQUE_DIR) |
| `0xC0000`* | данные игр (GAMES_START, режим имён 2) |
| верх флеш | область сохранений (battery saves) |

<aside>

* Для `name_mode = 1` под каталог имён резервируется меньше места, поэтому `GAMES_START` смещается ниже.

</aside>

## Диагностика проблем

- **ROM не помещается** уменьшите число игр либо увеличьте `max_rom_mb` под размер вашего флеш-чипа.
- **Игра не запускается / глючит** проверьте её маппер и добавьте запись в `nes-fixes.json`.
- **Кракозябры вместо кириллицы** убедитесь, что `patch = 1` и `font.png` содержит нужные тайлы.
- **Неверная скорость музыки** проверьте автоопределение региона: для стабильности можно увеличить `detect_frames`, либо задать `music_rate` вручную (`60` для NTSC, `50` для PAL). Если PAL-консоль путается с Денди — `detect_threshold = safe`.

## Поддерживаемые мапперы

Билдер знает раскладку регистров для всех мапперов, которые умеет железо CoolGirl. Если маппер игры есть в этом списке она соберётся «как есть». Если нет она не заработает.

<aside>

**Поддерживаются 50 мапперов:** 0, 1, 2, 3, 4, 5, 7, 9, 10, 11, 18, 21, 22, 23, 25, 30, 32, 33, 34, 36, 38, 42, 48, 65, 66, 67, 69, 70, 71, 73, 75, 78, 79, 83, 87, 89, 90, 93, 97, 112, 118, 133, 146, 152, 163, 184, 189, 206, 228, 241.

</aside>

Самые ходовые: `0` (NROM), `1` (MMC1), `2` (UxROM), `3` (CNROM), `4` (MMC3), `7` (AxROM), `9` (MMC2), `11` (Color Dreams). Это стандартные номера мапперов iNES посмотреть номер конкретной игры можно например **[Nes ROM Maker](https://vfiuchcikicshuusrch.ddns.net/Nintendo/nrm)**.

## Как игры размещаются во флеше

Размещение это точная копия алгоритма **ClusterM Combiner**:

- PRG-банки сортируются **по убыванию размера** и укладываются методом **first-fit** от начала области игр; каждый блок выравнивается по своей степени двойки.
- CHR-данные заполняют «дыры» между PRG-блоками шагом `0x2000` (8 КБ) флеш используется плотно.
- Первые **128 КБ** флеша зарезервированы под загрузчик и меню (LOADER); игры идут после `GAMES_START`.
- Идентичные блоки не дублируются (см. ниже).

## Дедупликация одинаковых игр

Перед укладкой билдер считает SHA1 каждого PRG и CHR блока. **Одинаковые блоки кладутся в один и тот же офсет** флеша, место не тратится дважды. Срабатывает автоматически, даже если в папке лежат полные дубликаты или разные ромы с одинаковой графикой.

В логе появляется строка вида:

```
Размещение (ClusterM-style + дедуп): PRG 250→241 уник. (дублей 9), CHR 240 уник. (дублей 10)
```

<aside>

Дедуп считается **по содержимому**, а не по имени файла. То есть `Mario (U).nes` и `Mario (J).nes` с одинаковыми данными схлопнутся в один блок, а в логе дубль подпишется именем оригинала, с которым делит офсет.

</aside>

## Как работают сохранения (battery saves)

- Игры «с батарейкой» получают слот сохранения в **энергонезависимой области наверху флеша**.
- Слоты выделяются секторами: **один сектор 128 КБ = 4 battery-игры**. Резерв печатается в логе: `резерв сейвов: N КБ (M × 128 КБ для K battery-игр)`.
- Лимит задаётся `[saves] max_save_games` (жёсткий максимум **255**). Если battery-игр больше лишние не получат сохранений, с предупреждением в логе.

## Определение региона: NTSC / PAL / Денди

Регион определяется **автоматически на старте меню**, вручную задавать его не нужно:

- Замер идёт через CPU-cycle counter с **отключённым NMI** на splash-экране: за фиксированное число кадров (`detect_frames`, по умолчанию **8**) считается, сколько раз успеет прокрутиться цикл из 12 тактов.
- **Пороги вычисляются из модели тактов CPU** (NTSC ≈ 29780, PAL ≈ 33247, Денди ≈ 35464 такта/кадр). При `detect_frames = 8` ожидаемые значения: **NTSC ≈ 78, PAL ≈ 87, Денди ≈ 92**; границы ставятся посередине между номиналами и автоматически пересчитываются при смене `detect_frames`.
- `detect_threshold` задаёт, куда поставить границу PAL/Денди: `default` ровно посередине (симметричный запас, рекомендуется); `safe` на ~2 единицы выше, к Денди (больше запас у PAL, меньше у Денди). `safe` нужен, только если конкретную PAL-консоль детектор путает с Денди.
- `detect_frames` (`4`–`16`) задаёт окно измерения: больше кадров → больше зазор между NTSC/PAL/Денди и устойчивее определение, но дольше чёрный экран на ресете.
- `detect_median = 1` делает **3 замера и берёт медиану** защита от случайных глитчей (стоит дополнительное время измерения, кратное `detect_frames`).
- Если измеренное значение вне разумного диапазона, детектор отдаёт `UNDETECTED`, и музыка играет в нативном темпе без поправок.
- От региона зависит темп музыки (`music_rate = auto`): **NTSC = 60 Гц**, **PAL / Денди = 50 Гц**.
- **Тип консоли нужен также для:** детекта сохраняется в `CONSOLE_TYPE_RAM` и при запуске игры сверяется с флагами совместимости из `nes-fixes.json` (`will_not_work_on_dendy` / `…_ntsc` / `…_pal` / `…_new_dendy`). Если игра несовместима с текущей консолью, вместо запуска показывается экран `INCOMPATIBLE CONSOLE` (см. ниже).

## Бегущая строка длинных имён (marquee)

<img width="480" height="420" alt="marquee" src="https://github.com/user-attachments/assets/17c4a85f-7016-4035-9e41-41b321b74300" />


При `name_mode = 2` имена длиннее `name_visible` (по умолчанию 11) символов прокручиваются:

- Включается ключом `[marquee] enabled = 1`.
- Скорость `speed` (кадров между сдвигами; меньше = быстрее, разумный диапазон 8–30).
- При переходе курсора на новую строку движок восстанавливает предыдущую строку из буфера, поэтому соседние имена не «смазываются».
- При `name_mode = 1` (короткие 11-символьные имена) прокрутка не нужна и отключается.

## Форматы вывода: `.nes` и `.bin`

- `format = nes` файл с заголовком **NES 2.0**: запускается в эмуляторе, понимающих заголовок. Формат по умолчанию.
- `format = bin` — **сырой дамп флеша без заголовка**: для прямой прошивки в чип программатором.
- `round_to_pow2 = 1` округляет итоговый размер до ближайшей степени двойки — нужно некоторым старым программаторам; по умолчанию `0` (минимальный размер файла).

## Как читать лог сборки

В консоли при сборке появляются ключевые строки:

| Строка в логе | Что означает |
| --- | --- |
| `✅ … mapper=4 … CRC=a1b2c3d4` | игра принята; показаны её маппер и CRC32 (CRC можно копировать в `nes-fixes.json`) |
| `[FIX …]` | к игре применена запись из `nes-fixes.json` |
| `📝 Создан шаблон списка…` | при первой сборке создан `games.list` / `games.csv` |
| `Размещение (… + дедуп): …` | статистика укладки и дедупликации |
| `резерв сейвов: …` | сколько флеша отдано под battery-сохранения |
| `⚠️ … не найден` | файл из списка отсутствует в `roms/` → пропущен |
| `ℹ️ … не из списка` | файл есть в `roms/`, но не указан в списке → не вошёл в сборку |
| `❌ … не помещается` / `Слишком много battery-игр` | фатальные ошибки сборки (см. «Диагностика») |
